# 书架面板体验评审（2026-11-07）

## 主链路

一个不懂技术的读者打开「我的书架」，把想读、在读、读完的书记下来，标出进度和评分，并在需要时看到今年读了多少。理想情况下：添加一本书 3–7 步，删除 2 步，查看今年读完的数量 0 步（页面上直接可见）。

评估环境：`dev/harness.mjs`。它加载真实的 `client.js` 和 `index.js`，主题变量取 DSH 的真实值（`dsh-client-ui-theme`），可以切换浅色/深色、中文/英文/伪本地化。改动之前，测试页把宿主主色伪造成蓝色 `#3b6ef5`，而真实 DSH 是近黑/近白，所以之前在测试页里看到的颜色并不是用户看到的颜色。

## 术语表

| 概念 / 动作 | 中文 | English | 依据 |
|---|---|---|---|
| 三种状态 | 想读 / 在读 / 已读 | Want to read / Reading / Finished | 豆瓣、微信读书用「想读 / 在读」；Apple Books 用「Want to Read / Finished」 |
| 新建一本书 | 添加 | Add | Apple 和 Microsoft 的风格指南都用 Add 表示往集合里加东西 |
| 修改 | 编辑 | Edit | 同上 |
| 删除 | 删除 | Delete | 同上；与「撤销 / Undo」配对 |
| 联网查资料 | 补全信息 | Look up details | 原来混用「更新信息」「联网补全」两个说法，现统一 |
| 批量读入 / 写出 | 导入 / 导出 | Import / Export | 通用说法 |
| 书里摘下来的原文 | 摘录 | Quotes | Goodreads 用 Quotes |
| 视图 | 按状态 / 列表 / 封面墙 | By status / List / Covers | 「看板」对普通读者是职场用语 |

动词不带催促语气（没有「立即」「马上」），按钮文字不用全大写。

**说明：**
- 上表的「依据」一栏是凭对这些产品的了解写的，没有逐条去 Apple 和 Microsoft 的官方术语库核对原文。
- 两种语言的文案都需要母语者再审一遍（见文末）。

## 设计变量

所有变量定义在 `client.js` 的 `CSS` 开头，深色模式跟随宿主的 `body[data-ds-dark-theme]`。

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bs-bg` | #faf8f5 | #1a1917 | 页面背景 |
| `--bs-surface` | #fffefc | #22201e | 卡片、弹窗、输入框 |
| `--bs-sunken` | #f2efea | #2b2926 | 分段控件、标签、提示条 |
| `--bs-line` / `--bs-line-strong` | #e6e1d9 / #d3ccc1 | #36332f / #4a463f | 分割线、边框 |
| `--bs-ink` / `--bs-ink-2` | #2b2722 / #6b6359 | #efebe5 / #ada499 | 主文字 / 次要文字（在所有表面上 ≥ 5.1:1） |
| `--bs-accent` | 黛绿 #426666 | 青碧 #48c0a3 | 唯一强调色：主按钮、在读、进度、统计柱 |
| `--bs-danger` | 胭脂 #9d2933 | #e8857f | 只用于表单错误 |
| 字号 | 12 / 14 / 17 / 24 | | 说明文字 / 正文和控件 / 弹窗标题 / 页面标题和统计数字 |
| 圆角 | 6 / 8 / 12 / 16 | | 小按钮 / 控件 / 卡片 / 弹窗；分段控件外 10、内边距 3、内 7（同心） |
| 控件高度 | 32（触屏 44） | | |

**强调色的选择和出处：**
- 浅色用黛绿，因为它在浅色的三种表面上对比度为 5.5–6.3:1。
- 深色时铜绿在下沉表面上只有 4.21:1，不达标，所以改用同色系的青碧（6.4–7.8:1）。
- 色值来自常见的中国传统色色表，没有对照印刷色卡核实。

## 验证

### 冷启动测试

方法：另起一个对本次改动毫不知情的 Agent，只给它产品和三个目标，不给任何说明。三个目标是：

1. 添加三本书，分别是读完、在读、想读；
2. 删掉其中一本；
3. 说出今年读完了几本。

改前、改后各跑一次。两次都从空数据文件和全新的浏览器存储开始。

| | 改前 | 改后 |
|---|---|---|
| 三个目标是否完成 | 完成 | 完成 |
| 总步数 | 46（其中 25 步在删除示例书） | 18 |
| 犹豫次数 | 10 | 4 |
| 要清理别人留下的东西 | 8 本示例书 | 无 |

改后那次的 4 处犹豫，后来改掉了 3 处：
- 新书的开始日期被默认填成今天；
- 「删除」看起来不像按钮；
- 「读过的页数 0」让人以为统计错了。

剩下 1 处没改：读完日期默认是今天，读完很久的书要用户自己改日期。

**测试过程中的问题：**
- 第一次两次测试同时跑，共用了同一个浏览器，结果作废。
- 第二次改前的测试被上一轮残留的浏览器存储污染，也作废。
- 上表数据来自第三轮，各自单独、干净地运行。
- 两次测试都由 Agent 完成，没有真人参与。

### 自动检查

`node dev/audit.mjs --full` 覆盖：
- 6 个尺寸：375、390、768、1280、1440、1920；
- 3 种语言：中文、英文、伪本地化（英文加长 40%）；
- 浅色和深色；
- 11 个状态。

共 264 屏。最后一次完整跑完的结果：

| 检查 | 改前（88 屏子集） | 改后（264 屏） |
|---|---|---|
| 每屏最多字号种类 | 12 | 4 |
| 每屏强调色色相数 | 3 | 1 |
| 冷蓝灰 | 每屏都有 | 0 |
| 对比度不达标的元素（每屏最多） | 44 | 0 |
| axe 严重和关键问题 | 每屏都有 | 0 |
| 界面文字被截断 | 0 | 4 屏 |
| 小于 24px 的点击目标（每屏最多） | 17 | 1 |
| 斜体 / 全大写 | 全大写眉标 | 只剩「JSON」 |
| 「·」 | 8 屏 | 0 |
| 控制台错误 | 测试页 favicon 404 | 0 |

**改后表里没清零的三项：**
- **4 屏截断**：只出现在伪本地化、375–390px 宽的首次打开页。之后已经改了（欢迎文案改为占满宽度），但用户叫停了审计，**这个修复没有复验**。
- **1 个小点击目标**：导入弹窗里 16×16 的勾选框。它在一个更大的可点击 label 里，整行都能点。
- **全大写「JSON」**：这是文件格式缩写，保留。

最后一轮还改了几处，没有重新截图，也没有重新审计：
- 按钮文字过长时允许换行；
- 窄屏下次要操作只显示图标；
- 窄屏列表收起进度列；
- 欢迎页文案改为占满宽度。

`npm test`：20 项全部通过，其中新增 2 项：首次打开是空书架；单复数和千位分组。

## 怎么复现

```bash
node dev/audit.mjs --shots --out /tmp/after
```

```bash
git show <改动前的提交>:client.js > /tmp/before.js && node dev/audit.mjs --client /tmp/before.js --shots --out /tmp/before
```

```bash
node dev/compare-pdf.mjs /tmp/before /tmp/after docs/review/before-after.pdf docs/review/pairs.json
```

审计需要 Playwright（`PLAYWRIGHT_DIR`）和 axe-core（`AXE_FILE`），路径默认值写在 `dev/audit.mjs` 开头。
